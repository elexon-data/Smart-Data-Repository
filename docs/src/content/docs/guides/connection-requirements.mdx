Use only documented, versioned routes when connecting to SDR APIs. Protect your credentials and handle SDR data in line with its access and usage terms.

## Connect securely

- Your client initiates the connection to the confirmed SDR hostname over the public internet using HTTPS on TCP port 443. SDR does not initiate a connection to your system, and you do not need a private circuit.
- Use TLS 1.3 or later. Validate the server certificate and hostname with your trusted certificate store. Do not disable validation or fall back to an older TLS version.
- Client certificates and mutual TLS are not required. Use the [authentication guide](../authentication/) for protected calls.

## Use the documented API

The API host is separate from this documentation site. Use the server URL for your environment and a documented path such as `/api/catalog/v1/datasets`. Keep the major version in the URL and do not rely on unversioned paths.

The [API reference](../../reference/) defines each operation's parameters, scopes, and response schemas. Confirm availability for your environment and account before integrating.

## Fair use

Use the SDR APIs in line with fair use.
